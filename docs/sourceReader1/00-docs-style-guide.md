# 源码文档规范与定位约定

> 本文档定义本目录（`docs/sourceReader1/`）所有源码阅读文档的统一规范。
> 文档日期：2026-10-27。仓库基线：`main @ 2cab11ca4`（Rust 工具链 1.95.0 固定提交）。

## 一、事实红线

1. **严禁编造、臆测、空泛**。所有事实（接口有无、字段类型、默认值、联动条件、表名、服务归属）必须经 Grep/Read/实测查证。无法证实的显式写「当前源码无法确定」或「未实测，待补」。
2. **禁止「同上 / 略 / 以此类推」替代核心内容**。
3. **源码锚点用「符号 + 偏移」，不用裸行号**（行号随重构漂移）：
   - 函数内：`path/file.rs 函数：Foo 偏移：+24`（`+0` = 函数签名行，目标行 − 签名行 = 偏移）。
   - 连续片段：`Foo+0~+20`。
   - 非函数代码：`Struct：Node` / `Const：X` / `Mod：rpc`。
   - 调用关系标双方：`调用方 Foo+6 ↓ 被调用方 makeNode`。
   - 第三方依赖注明版本：`依赖：crate`。
   - 文末源码索引可给 `文件:符号:绝对行号` 方便跳转复核（正文锚点仍用符号+偏移）。
4. **图不能少**：每篇 ≥1 张图。逻辑流/报文/管道用 ASCII 字符图；架构用 Mermaid `flowchart`、调用用 `sequenceDiagram`、状态用 `stateDiagram-v2`、多表关系用 `erDiagram`。
5. **实测数据必须标注来源与日期**：写明实例名、日期、只读查询；无权限就写「未实测，待补」，绝不编数。
6. **未逐行阅读的反射/生成/内部实现**，显式标注「未读取，不臆测」。

## 二、锚点写法

本仓库为 Rust 工作空间（`codex-rs/`，122 个 crate）。锚点路径一律从仓库根写相对路径，如：

```
codex-rs/core/src/session/turn.rs 函数：run_turn 偏移：+0
codex-rs/tui/src/app.rs 函数：handle_tui_event 偏移：+0
codex-rs/sandboxing/src/manager.rs 函数：transform 偏移：+0
```

计算规则：`偏移 = 目标行 − 函数签名行`。`+0` 指函数签名行本身。

## 四、设计特性与值得关注的点

每篇文档末尾附「设计特性与值得关注的点」清单，记录历史分层产物、隐式约定、静默行为等非缺陷但值得留意的源码事实。清单用「要点 / 结论 / 依据」三列，依据列给出源码锚点（符号 + 偏移），不设严重度分级。
